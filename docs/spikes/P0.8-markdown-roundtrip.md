# Spike P0.8 — Markdown round trip with TipTap

**Question:** if notes are stored as Markdown and edited in a rich (WYSIWYG) editor, does the user's Markdown survive?

**Setup:** TipTap 3.31 with `@tiptap/markdown`, StarterKit, task lists, tables, images, and a prototype `[[wikilink]]` node. A corpus of 18 documents is parsed into the editor and serialised back, twice. Test: `app/src/spikes/markdownRoundTrip.test.ts`.

**Verdict:** keep TipTap (decision 0005). Nothing is lost once the Image and WikiLink extensions are loaded, and every document is stable after its first save.

| Document | Byte-identical | Stable after 1st save | Notes |
|---|---|---|---|
| Headings, emphasis, bullets, ordered (starting at 3), task lists (nested), quotes, fenced code, links + images, rule, hard break, escapes, unicode/emoji, meeting note, `@date` `#tag` `[[link]]` | Yes | Yes | |
| Table | No | Yes | Columns padded to equal width (cosmetic) |
| `*` bullets | No | Yes | Become `-` bullets (cosmetic) |
| "Underline" heading (`Title` + `=====`) | No | Yes | Becomes `# Title` (cosmetic) |
| Inline HTML (`<kbd>`) | No | Yes | **Tags stripped, text kept** |

**Found and fixed during the spike:**

- Without the Image extension, `![sketch](…)` was **silently dropped**. The corpus test now asserts that every link and image URL survives.
- Without a WikiLink node, `[[Launch plan]]` was stored as `\[\[Launch plan\]\]`. The prototype node in `app/src/spikes/wikiLink.ts` fixes this, and should ship in Phase 1 even though link features come in Phase 5.

**Carry into Phase 1:**

- Load Image and WikiLink.
- Keep the corpus test in CI, with a new case for each node.
- Plain-text notes and source mode give byte-exact storage for anyone who needs it.
- Consider warning when an imported file contains inline HTML.
